Python it is! It's honestly the better route if you want to cleanly handle errors or maybe tweak the text later.

To make this work, you'll still need the Tesseract engine installed on your Mac (brew install tesseract), plus a couple of Python libraries to handle the images and the OCR wrapper.

1. Install the Python packages

pip install pytesseract Pillow

2. The Python Script

Save the following code as read_screenshots.py in your terminal (you can just type nano read_screenshots.py, paste this in, hit CTRL+O, Enter, and CTRL+X):

import os
import glob
from PIL import Image
import pytesseract

# Set up paths (Mac is usually capitalized 'Desktop', but we'll check both just in case)
desktop_path = os.path.expanduser("~/Desktop") 
if not os.path.exists(desktop_path):
    desktop_path = os.path.expanduser("~/desktop")

output_txt = os.path.join(desktop_path, "all_screenshot_text.txt")

# Grab all the screenshots from that specific date
search_pattern = os.path.join(desktop_path, "Screenshot 2026-03-04*.png")
image_files = sorted(glob.glob(search_pattern))

if not image_files:
    print("No screenshots found. Double-check your path or file names!")
else:
    print(f"Found {len(image_files)} screenshots. Ripping text now...\n")
    
    with open(output_txt, 'w', encoding='utf-8') as outfile:
        for img_path in image_files:
            filename = os.path.basename(img_path)
            print(f"Reading: {filename}")
            
            outfile.write(f"\n\n{'='*50}\n")
            outfile.write(f"  FILE: {filename}\n")
            outfile.write(f"{'='*50}\n\n")
            
            try:
                img = Image.open(img_path)
                text = pytesseract.image_to_string(img)
                outfile.write(text)
            except Exception as e:
                error_msg = f"[FAILED TO READ: {e}]"
                outfile.write(error_msg)
                print(f" -> {error_msg}")

    print(f"\nDone! Everything is saved to: {output_txt}")

3. Run it

python read_screenshots.py

This will spin through all 31 of those screenshots, grab the text, and output a single, neatly formatted all_screenshot_text.txt file right on your desktop.

The most efficient approach depends on factors like privacy (local vs. online), setup effort, batch size (you have 31 files), and hardware. Online tools are often the fastest for one-off batches with minimal setup, while local scripting offers more control and scalability for repeated use.

1. Quickest No-Code Option: Online Batch OCR Tools

For a one-time extraction without installing anything, use a web-based AI-powered OCR service. These handle multiple uploads in parallel, process via cloud servers (often with GPU acceleration for speed), and output text files.

Recommended Tool: ImageToText.io

  • Upload up to 50 images simultaneously (covers your batch).
  • Supports PNG, JPG, and other formats; handles screenshots well.
  • Extracts text with high accuracy using AI models, then downloads as .TXT.
  • Free for basic use; premium for larger batches or priority speed.
  • Time estimate: 1-5 minutes for 31 images, depending on file size.

Alternative: ImgToText.net or CardScanner.co — Similar batch support, AI-driven for blurry screenshots. Free tiers available; processes in seconds per image when batched.

2. Local Scripting for Efficiency and Privacy

If you prefer offline processing or have sensitive content, script it locally. This is efficient for threading/parallelism, especially since your Git output mentions multi-threading (up to 16 threads).

Setup (One-Time):

  • Install Tesseract OCR: sudo apt update && sudo apt install tesseract-ocr
  • Install Python libraries: pip install pytesseract pillow multiprocessing
  • Or use EasyOCR: pip install easyocr

Efficient Batch Script (Python with Multiprocessing):

import os
import pytesseract
from PIL import Image
from multiprocessing import Pool, cpu_count

desktop_path = os.path.expanduser('~/Desktop')
output_dir = os.path.join(desktop_path, 'extracted_text')
os.makedirs(output_dir, exist_ok=True)

images = [f for f in os.listdir(desktop_path) if f.startswith('Screenshot 2026-03-04') and f.endswith('.png')]

def extract_text_from_image(filename):
    img_path = os.path.join(desktop_path, filename)
    img = Image.open(img_path)
    text = pytesseract.image_to_string(img)
    output_path = os.path.join(output_dir, f"{filename[:-4]}.txt")
    with open(output_path, 'w') as f:
        f.write(text)
    return f"Processed {filename}"

num_threads = min(16, cpu_count())
with Pool(num_threads) as p:
    results = p.map(extract_text_from_image, images)

print("Extraction complete. Text files saved in:", output_dir)

Release notes are summaries of changes in a new version of your software, typically including features, bug fixes, and other updates. Automating their generation saves time, ensures consistency, and reduces manual errors.

1. Using GitHub's Built-in Automatic Release Notes

GitHub offers a simple, no-code way to generate release notes automatically from merged pull requests (PRs), contributors, and commits since the last release.

Steps:

  1. Navigate to your repository on GitHub.
  2. Click Releases on the right sidebar.
  3. Select Draft a new release.
  4. Enter a tag (e.g., v1.0.0) and title.
  5. Click Generate release notes above the description field.
  6. Review/edit the generated notes, then publish.

2. Automating with GitHub Actions

name: Create GitHub Release

on:
  push:
    tags:
      - 'v*'

jobs:
  release:
    runs-on: ubuntu-latest
    permissions:
      contents: write

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Create Release
        uses: ncipollo/release-action@v1
        with:
          generateReleaseNotes: true
          token: ${{ secrets.GITHUB_TOKEN }}

Push a tag: git tag v1.0.0 && git push --tags

3. Third-Party Tools

release-it: A CLI tool for versioning, tagging, and publishing releases.

npm install --save-dev release-it
npx release-it

semantic-release: Automates based on commit messages using Conventional Commits like feat: add login.

npm install --save-dev semantic-release
